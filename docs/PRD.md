## 1. 제품 개요

### 1.1 한 문장 정의
송전선로 주변에서 취득한 **LiDAR LAS/LAZ 점군을 선로·철탑 정보와 연결하여**, 웹 기반 2D 지도 및 독립적인 3D 점군 분석 화면에서 식생·전선·철탑·지형을 구분하고 **수목–전선 이격거리와 주변 장애물 위험을 분석·시각화·저장**하는 PoC 시스템.

### 1.2 해결할 문제
- 측량 성과가 LAS/LAZ 파일 형태로 존재해 담당자가 브라우저에서 쉽게 조회·비교하기 어렵다.
- 측량파일이 어떤 송전선로 또는 철탑 구간에 해당하는지 연관관계와 이력을 관리하기 어렵다.
- 점군 안의 식생, 전선, 철탑, 지면 등의 구분이 없거나 품질이 일정하지 않을 수 있다.
- 수목과 실제 전선 사이의 공간상 이격을 사람이 수동으로 확인해야 하며 위험 구간을 체계적으로 검토하기 어렵다.
- RGB/NIR 속성 유무에 따라 가능한 분석이 달라지는데, 데이터의 한계를 표시하는 화면이 필요하다.
- 폐쇄망에서 외부 지도·분석 서비스 없이 데이터 조회와 분석이 가능해야 한다.
- 운영 환경의 2D 선로 지도는 기존 **TOMS**를 이용하며, PoC 2D 지도는 개발·검증 시에만 독립 구축한다.
- 3D 점군에서 사용자가 선로·수목 등의 두 측정점을 직접 지정해 즉시 거리와 연결선을 확인해야 한다.

### 1.3 목표
1. **선로/철탑 선택 후 LAS/LAZ 업로드, 매핑, 메타데이터 관리**.
2. **2D 지도**에서 선로·철탑과 데이터셋 커버리지, 분석 결과 위치 표시.
3. **별도 3D 점군 화면**에서 대용량 데이터 탐색, 점 선택 및 속성 기반 색상 표시.
4. **식생·전선·철탑·지형 등의 분류 표시** 및 미분류/불확실 구간 식별.
5. 분석 대상으로 반입하는 LAS/LAZ에는 **Red와 NIR 값이 포함된다는 사업 가정**을 적용하고 NDVI 등 식생지수를 계산·표시한다. 파일별 실제 속성 및 분광값의 유효성은 업로드 시 검증한다.
6. 검증된 전선 형상과 수목 점군 사이 **3D 최소 이격거리** 및 근접 위험 구간 산출.
7. 분석 결과를 도표·지도·보고서용 데이터로 저장하고 재조회.
8. 외부 개발 → 폐쇄망 반입을 고려한 재현 가능 구축.

### 1.4 명시적 비목표
- **철탑 좌표 또는 송전선로 선형 등 운영 GIS 원본 데이터를 수정·정비하는 기능**.
- LiDAR 원시점의 수동 편집·원시 LAS 자체 재작성(초기 PoC).
- 법적 안전거리·규정 위반의 자동 확정 판정(기준 및 검수 절차가 미확정).
- 수목 수종 자동 판별, 생육량·수고 자동 추정, 나무별 개체 추적(후속 검토).
- 모든 LiDAR 센서 일반에 NIR가 존재한다고 주장하는 것(본 PoC의 **납품 데이터 조건**으로 Red/NIR를 전제함).
- 검증되지 않은 CRS, 지오이드/고도 기준, 전선 위치를 기준으로 정확도를 보증하는 계산.
- 생산망 데이터베이스로 분석 결과 자동 반영.

## 2. 주요 사용자 및 업무 흐름

| 사용자 | 사용 목적 | 주요 기능 |
|---|---|---|
| 송전 설비/수목 관리 담당자 | 수목 근접·장애물 위험 확인 | 선로 검색, 위험 위치 탐색, 이격거리 결과 열람 |
| LiDAR 측량성과 관리자 | 성과 등록과 품질 점검 | LAS 업로드, 대상 매핑, CRS/채널/분류 메타데이터 점검 |
| GIS 분석 담당자 | 점군 분류와 이격 분석 검증 | 3D 시각화, 전선·식생 점 선택, 분석 매개변수 검토 |
| PoC 시스템 운영자 | 데이터·분석환경 운영 | 저장소·작업 상태, 폐쇄망 서비스, 백업·로그 |

### 2.1 대표 시나리오 — TOMS 기반 LAS 등록·조회·이격거리 분석
1. 사용자가 **TOMS → LiDAR 업로드 목록** 화면을 연다. 사업소·선로명으로 검색하여 기존 업로드 이력을 확인한다.
2. 새 측량 성과를 등록하려면 **LAS 입력** 버튼을 누른다. 입력 팝업에서 **대상 선로를 선택**하고 **사업명을 직접 입력**한 뒤 `.las` 또는 `.laz` 파일을 **1개 이상** 선택한다.
3. 업로드 버튼을 누르면 필수항목, 확장자, 크기, 파일 헤더, Red/NIR 속성, 좌표정보 등을 검사하고 **PoC 전용 DB/원본 파일 저장소**에 메타데이터와 선로 매핑을 기록한다. 사업소는 선택된 선로의 소속정보에서 가져오는 것을 기본안으로 한다(기준정보 확인 필요).
4. TOMS 업로드 목록은 **업로드 건 단위(1행 = 1업로드 건)**로 **사업소 / 선로명 / 파일명 목록(복수 가능) / 총용량 / 최소이격거리**와 처리 상태를 표출한다. 최소이격거리는 분석이 완료되기 전에는 **'미산출'**로 표시한다. 분석 실패 또는 검증 대기는 구분 표시한다.
5. 사용자가 **업로드 건 1건을 체크**하고 **3D 조회** 버튼을 누르면 새 창에서 해당 업로드 건에 포함된 LAS/LAZ **전체 파일을 함께 로드·표출**한다. 동일 선로에 속한 다른 업로드 건의 파일은 로드하지 않는다.
6. 3D 화면은 전달받은 **업로드 그룹 ID(upload_id)**로 서버에서 권한·등록상태를 확인하고, 그룹에 속한 파일 ID 전체와 선로정보를 조회하여 로드한다. URL 파라미터로 원본 저장경로나 비밀정보를 전달하지 않는다.
7. 3D 점군을 RGB / NDVI / 분류(식생·전선·철탑·지면 등)로 표출하고, 휠 스크롤 확대·축소, 휠 버튼 드래그 회전, **2개 점 클릭 수동 직선거리 측정**을 제공한다.
8. 자동 최소이격거리 분석이 가능한 자료에 대해서만, 전선–수목 간 **3D 최소이격거리** 및 위험 후보를 산출하고 처리 상태와 함께 목록에도 반영한다.
9. 분석 결과는 PoC 전용 PostGIS에 저장한다. TOMS의 운영 GIS 원본 데이터는 수정하지 않는다.

### 2.2 예외 시나리오
- 대상선로 미선택·사업명 공란·파일 미선택: 업로드 전 오류를 표시하고 등록을 차단한다. (선로 미선택 시 매핑 대기 등록은 현 업무 흐름에서 제외)
- LAS CRS 불명확 또는 전선/식생 수직 기준 불일치: 거리 산출 차단, 문제 내용 제시.
- Red/NIR 부재: 필수 데이터 계약 위반으로 NDVI 분석을 차단하고 오류·누락 항목 표시. 원본 파일 보존/등록 가능 여부는 상세 요구사항에서 결정.
- 분류 코드 없음/신뢰도 낮음: 미분류로 표시하고 자동 분류 기능 여부에 따라 분석 차단 또는 검토 요청.
- 전선 점군이 희소하거나 누락: 결과를 '산출 불가/검토 필요'로 표시; 임의 직선 보간 결과를 확정값으로 제공하지 않음.
- LAS 파일이 큰 경우: 비동기 처리 작업으로 등록하고 진행상태·오류·재시도 표시(후속 구현).

## 3. 데이터 입력과 품질 전제

### 3.1 필수 입력 자산
| 자산 | 형식(예시) | 용도 | 품질 확인 |
|---|---|---|---|
| 측량 점군 | LAS/LAZ | 지형·시설물·식생 분석 | 점 수, XYZ, 헤더, CRS, 수직 기준, 분류, RGB/NIR |
| 송전선로 기준정보 | PostGIS 또는 승인된 별도 GIS 소스 | 업로드 연결 및 선로 탐색 | 선로 ID·구간 ID·좌표 정확도 |
| 철탑 기준정보 | PostGIS 또는 승인된 별도 GIS 소스 | 구간 시작/끝, 주변 검색 | 철탑 ID·선로 연결 관계 |
| 항공정사영상(선택) | GeoTIFF (EPSG:5186 후보) | 2D 배경지도 | 실제 GeoTIFF 공간참조와 이용조건 |
| 일반지도(선택) | FileGDB → PostGIS 등 | 2D 지도 도로/지형/행정 레이어 | GDB 구조, 스타일/라이선스 |
| 전선 3D 형상 | 검증된 전선 점 분류 또는 3D 모델 | 이격거리 분석 기준 | 수직 기준, 누락·잡음, 측량 시점 |

### 3.2 정확도/좌표계
- 2D 작업지도는 **EPSG:5186**을 목표로 한다. 현재 저장소 GIS API와 기존 피처 DB는 **EPSG:4326**이다. 지도·API 간 변환은 좌표 수치를 실제 변환해야 한다.
- LAS는 EPSG가 없거나 잘못 기재될 수 있다. **측량성과표, 기준점/제어점, X/Y 범위** 등 외부 증거를 통해 CRS와 축 순서를 검증한다.
- 3D 거리는 같은 수평/수직 좌표 참조, 미터 단위, 높이 기준으로 정규화 후 산정한다.
- **정표고/타원체고** 불일치, 측량 시기·전선 처짐·풍하중·온도 등은 별도 오차요인이며 PoC 정확도 보증 범위를 검토해야 한다.
- 이격거리 계산 결과에 계산 근거 및 **데이터 신뢰성 등급**을 기록한다.

### 3.3 RGB/근적외선과 식생지수 구분
- 사업 입력 가정: **모든 분석 대상 LAS/LAZ에는 Red와 NIR 값이 반드시 존재**한다. 업로드 시 속성 존재 및 유효 범위를 검증한다. 부재한 파일은 NDVI 분석 불가로 표시한다.
- **NDVI = (NIR − Red) / (NIR + Red)**. 사용 전에 NIR/Red의 동일 위치 대응, 밴드 보정/정규화 및 값 범위 검증이 필요하다.
- LAS의 NIR/Red 속성 존재를 전제로 하지만 **분광 보정·촬영 조건 검증이 없는 수치를 식생 건강도 확정값으로 해석하지 않는다.** 별도 영상 매칭은 현재 범위 외이다.
- **식생지수와 객체 분류는 서로 다른 개념**이다. NDVI가 높다고 곧바로 '수목 객체'가 확정되지는 않으며, 전선·철탑 분리에는 LAS classification, 기하학적 분석 또는 검증된 분류 모델이 필요하다.
- LAS 표준 classification 코드의 의미는 데이터 생성 파이프라인에 따라 달라질 수 있으므로 원본 분류 스키마를 확인하고 매핑한다.

## 4. 제품 화면 및 정보 구조

### 4.1 TOMS 업무 진입 화면 / PoC 2D 검증 지도
- **운영 폐쇄망:** 기존 **TOMS 시스템이 2D 지도와 송전선로/철탑 검색·선택 업무를 담당**한다. 이 PoC의 독립 2D 지도를 그대로 운영 배포하는 것을 목표로 하지 않는다.
- **외부 개발·검증 PoC:** TOMS 접근이 어려운 개발환경에서 시험하기 위해 EPSG:5186 2D 기본지도(GeoTIFF 정사영상 / FileGDB 변환 일반지도 / GeoServer)를 선택적으로 구축한다.
- TOMS에 **LiDAR 업로드 목록 조회 화면**, **LAS 입력 팝업**, **3D 조회 버튼**을 추가하는 방향을 요구한다. 실제 TOMS 화면 수정 방식과 API/인증/배포 권한은 연계 설계에서 확정한다.
- 선로 ID, 사업소 정보, 사용자 세션의 취득과 전달 규칙은 TOMS 연계 계약으로 정의한다. 현재 PoC가 TOMS와 이미 연동된 것으로 간주하지 않는다.
- PoC 2D 지도에서 선택한 시설물 ID와 LAS 데이터셋 ID를 3D 분석 화면에 전달한다. 위치 전달 시 실제 좌표 변환과 CRS 검증을 수행한다.
- TOMS 운영 GIS 원본 수정·편집·자동 동기화는 범위에서 제외한다.

### 4.2 TOMS — LiDAR 업로드 목록 및 LAS 입력 팝업 [신규, 기구현 아님]
**업로드 목록**
- 진입: TOMS 메뉴(명칭 예: **LiDAR 업로드 목록**; 실제 메뉴명 확정 필요).
- 조회: 기존 등록된 데이터셋을 최신 업로드 순으로 표시한다. 검색조건은 **사업소, 선로명**을 기본안으로 한다.
- 필수 표시열: **업로드 건 선택 체크박스 / 사업소 / 선로명 / 파일명(복수 시 파일 목록 또는 대표명+N) / 총용량 / 최소이격거리**. 운영 편의를 위한 추가 열: **사업명, 업로드일시, 분석·검증 상태**.
- 파일 용량은 저장 바이트 수에 기반해 MB/GB로 일관되게 표시하고, 정확한 바이트 수는 상세보기에서 제공한다.
- 최소이격거리는 **자동 분석 결과의 데이터셋별 대표값(m)**을 우선안으로 한다. 미실행='미산출', 계산중='분석중', 검증실패='검증필요', 실패='분석실패', 대상없음='산출불가'로 구분한다. 수동 두 점 측정값을 목록 최소이격거리로 대체하지 않는다.
- 체크 및 **3D 조회**: 선택 0건 시 조회 불가, **업로드 건 1건** 선택 시 새 브라우저 창에서 `/3d?uploadId=<UUID>`와 같은 라우트로 이동(라우트명은 설계 시 확정). **선택 업로드 건 내 1~N개 LAS/LAZ 파일 모두 중첩 표시**한다. 업로드 건 2개 이상을 동시에 선택하는 기능은 초기 범위에서 제외한다.
- 체크박스 선택은 일시적인 UI 상태일 뿐 업로드나 분석 데이터를 변경하지 않는다.

**LAS 입력 팝업**
- 진입: 목록 상단 **LAS 입력** 버튼 → 모달 팝업.
- 필수항목: **대상선로**(검색·선택, 내부적으로 선로 ID 사용), **사업명**(사용자 입력 텍스트), **LAS/LAZ 파일**(파일 선택).
- 표시/자동 채움: 사업소(선택 선로 기준), 선택한 **1~N개 파일명·개별 용량·총용량**.
- `업로드` 시 버튼 중복 실행을 방지하고 진행/성공/실패를 표시한다. 완료 시 팝업을 닫고 목록을 새로고침하거나 완료 메시지 후 자동 반영한다.
- 선로 선택정보와 업로드 파일은 서버에서 최종 재검증한다. 사업명 길이·허용문자, 파일 상한, 한 파일의 복수 선로 허용, 중복 파일 처리 정책은 상세 요구사항에서 확정한다.
- 서버 데이터 모델에는 **사업소 ID, 선로 ID, 사업명, 업로드 그룹 ID, 파일별 ID, 개별 원본파일명, 개별 파일 크기, 총용량, 업로드 시각, 검증/분석 상태**를 연결 저장한다.
- 원본 LAS/LAZ는 별도 파일 저장소에, 관계형 업무 메타데이터와 분석 결과는 PoC PostGIS에 저장한다.

### 4.3 독립 3D 점군 분석 화면 [기구현 로컬 미리보기 / 핵심 신규]
- TOMS에서 **업로드 건 1건을 체크한 후 [3D 조회]**를 누르면 **새 브라우저 창**으로 독립 3D 점군 분석 화면을 연다. 화면은 **업로드 그룹 ID**를 기준으로 해당 건에 포함된 **모든 파일**과 선로 매핑을 조회한다. 다른 업로드 건의 파일은 조회하지 않으며, 잘못된/권한 없는 ID는 거부한다.
- PoC 단독 실행 환경에서는 동일한 목록/호출 흐름을 모의 화면으로 제공해 TOMS 없이도 기능을 검증한다.
- 점군 표현 모드: RGB, 높이, 강도(Intensity), LAS classification, NDVI(Red/NIR 필수 데이터 전제, 유효성 검사 필요).
- 식생·전선·철탑·지면의 **분류별 색상과 표시/숨김 필터**를 지원하며 미분류 상태를 명시한다.
- **수동 두 점 거리측정:** 측정 모드를 선택한 사용자가 점군의 첫 번째 점 A(예: 전선), 두 번째 점 B(예: 수목)를 클릭하면 두 점 사이 **3D 직선거리(m)**, 연결선과 각 점의 좌표·분류를 표출한다. 측정 다시 시작/취소/초기화를 제공한다.
- **자동 이격거리 분석과 분리:** 수동 측정은 선택한 두 점의 거리이며, 전체 수목/전선 간 **최소 이격거리**를 보장하지 않는다. 자동 위험도 산출은 별도 알고리즘과 검증 절차를 사용한다.
- **마우스 기본 조작 확정:** 휠 스크롤 = zoom in/out; **휠 버튼(가운데 버튼) 클릭 유지 + 드래그 = 카메라/장면 회전**. 클릭 단독으로 회전하는 것은 아니며, 이동(Pan) 조작은 우선 기본안으로 왼쪽 버튼 드래그를 검토하고 라이브러리와 측정 모드 충돌에 맞춰 확정한다.
- 점 측정 모드에서 클릭/드래그를 구분하고, 휠 드래그가 측정점으로 잘못 입력되지 않도록 한다. 카메라 회전 중심, 확대 민감도, 터치패드 대응은 상세 UI 설계에서 검증한다.
- 점군 선택/피킹 정확도는 데이터 LOD·실제 원본점 대응 방식에 따라 달라진다. 선택 결과에 사용된 실제 점/표시용 표본점 여부와 좌표계 검증 상태를 표시한다.
- 대용량 점군은 타일링/LOD 적용이 필요하며 초기 로컬 점군 미리보기와 명확히 구분한다.

### 4.4 분석 결과 화면 [계획]
- 선로별/철탑 구간별 최소거리, 임계값 이하 후보 개수, 최근 분석 일시.
- 위험 후보 위치 2D·3D 연결, 점군 스냅샷/근거, 분류/좌표계 품질 상태.
- CSV/GeoJSON 등 결과 내보내기(우선 형식 결정 필요); 보고서(PDF 등)는 후속.

## 6. 거리측정 및 이격거리 분석 상세 정의(초안)

### 6.0 수동 두 점 측정 — 즉시 화면 측정
- 사용자가 화면의 두 점 A, B를 피킹하여 `sqrt((xB-xA)^2+(yB-yA)^2+(zB-zA)^2)`로 **3D 직선거리**를 계산한다.
- 화면 표시점/표본점과 실제 원본점의 차이를 검토하고, 측정 좌표가 동일한 미터 단위의 유효 3D 기준인지 확인한다.
- 결과에는 A/B 좌표, 단위(m), 데이터셋, 선택점의 분류 및 측정 시각을 포함하며 화면에서 취소/재측정을 지원한다.
- 수동 측정은 두 **지정점 사이의 거리**이지 전선–수목의 전역 최소 이격거리 산출 결과가 아니다. 자동 산출과 UI 명칭을 구분한다.



### 6.1 분석 대상
- A: **전선 3D 형상** — 실제 점군에서 식별·검증된 전선 점 또는 명시적인 검증된 3D 전선 모델.
- B: **식생 3D 점군** — 검증된 수목/식생 분류에 속하는 점들.
- 목표: 동일 좌표 참조에서 **최소 유클리드 3차원 거리(m)** 및 해당 식생점/전선 위치를 구한다.
- **분류된 전선 점 간 희소 구간을 직선으로 이어서 실제 전선 처짐 형상을 보증하지 않는다.** 곡선 모델/보간 방식과 정확도는 추후 승인된 알고리즘 명세에서 결정한다.
- 거리 계산 단위(식생점별, 수목 군집별, 철탑 간 경간별, 선로별), 위험 판정 기준, 데이터 밀도 및 오차 공차는 결정 필요.

### 6.2 계산 절차
1. 입력 데이터 품질·좌표계·단위·수직 기준 일치 여부 검증.
2. 점군 분류 품질을 확인하고 식생과 전선(또는 검증 모델)을 선택.
3. 이상치·누락·경계에 대한 필터링 정책 적용(원본 보존).
4. 공간 색인/KD-tree 등 효율적 최근접 탐색으로 후보 거리 계산.
5. 산출값 검증(알려진 합성 기하 샘플, 수동 기준 측정), 데이터 신뢰성·오차 표기.
6. 승인된 임계값 또는 사용자의 임시 검토값에 따라 위험 **후보** 표시.
7. 결과·파라미터·입력 파일 버전·코드 버전 저장.

**중요:** PoC 위험 후보는 설비 안전 여부에 대한 법적 판정이 아니며, 법정·사내 안전기준과 측량 정확도가 확인되기 전까지 '위반 확정'으로 표기하지 않는다.

## 8. 서비스 아키텍처(방향, 아직 확정 설계 아님)


data input: LAS/LAZ + 선로/철탑 기준정보 + GeoTIFF/FileGDB 지도 자산

```text
[PoC 2D 검증 지도] --- 시설물 ID ---- [독립 3D 점군 분석 화면]
    (OpenLayers 후보)                        (CesiumJS)
             |                                   |
      [GeoServer WMS/WMTS]                 [LOD/점군 서비스]
             |                                   |
    [GeoTIFF / PostGIS]     [FastAPI 메타·분석 API]
                                        |         |
                                  [PostGIS]   [LAS 원본 저장소]
                                                 |
                                        [PDAL·분류·거리 분석 Worker]
```

- 현재 소스: React/Vite/Cesium + FastAPI + PostgreSQL/PostGIS, laspy 샘플 점군 미리보기, VWorld WMTS 연결.
- 미래 설계: 개발·검증용 2D OpenLayers(후보)/GeoServer, **폐쇄망 업무용 2D는 TOMS**, 독립 3D 분석 UI, LiDAR 분석 Worker(PDAL 후보), 대용량 점군 타일/LOD 파이프라인.
- 운영 TOMS와 3D 분석 간의 구체적 연동은 식별자/호출 방식/API 권한을 확인한 후 별도 구현한다.
- PDAL이 Cesium용 3D Tiles를 자동으로 만드는 것으로 가정하지 않는다. 점군 변환 도구/출력 포맷 및 라이선스 별도 검증.
- LAS/LAZ는 저장소에 보존하고 PostGIS에는 메타데이터·매핑·작업·분석 결과를 저장한다.
- 기존 일반 GIS Feature API는 회귀 방지를 위해 유지할 수 있지만 **사용자용 위치/선형 편집 화면은 개발하지 않는다**.

## 10. PoC 단계와 성공 기준

### Phase 0 — 현행 동작 안정화
- 기존 프런트 빌드, LAS 업로드/미리보기, GIS 조회 API 검증 및 실패 로그 기록.
- CRS 미검증 데이터를 자동 배치하지 않는 기존 동작 유지.

### Phase 1 — 선로·LAS 관리 및 3D 탐색
- 선로/철탑 더미 또는 승인된 기준정보 조회.
- 업로드 데이터셋과 선로/구간 매핑 및 검색.
- 2D 지도–별도 3D 화면 전환; 검증된 공간 기준에 따라 위치 연계.
- RGB/고도/강도/분류별 시각화; 누락 채널은 비활성화.

### Phase 2 — 분석 PoC 핵심
- NIR+Red 입력에서 NDVI 산출, RGB만 있는 샘플은 RGB 전용 식생 강조와 구분.
- 전선·식생 데이터의 확정/검증된 분류 기반 3D 거리 계산.
- 임계값 이하 위험 후보 2D/3D 조회 및 분석 이력 저장.
- 합성 기준 데이터와 현장 측량 샘플로 정확도·오차 수준 검토.

### Phase 3 — 대용량 및 폐쇄망 실증
- 비동기 작업·대용량 타일/LOD·재처리.
- 내부 GeoServer 일반지도/항공영상, 외부망 접속 없이 기능 검증.
- 이미지/의존성 패키징, 계정·권한·감사 정책 실증.

### 최소 성공 판정(시험 가능한 형태)
1. 하나의 송전선로 또는 철탑 구간을 선택하고 LAS/LAZ 1개 이상을 업로드하여 연관관계를 재조회할 수 있다.
2. 동일 데이터셋을 별도 3D 화면에서 열어 원본 점군을 탐색할 수 있다.
3. 제공된 채널/분류에 따라 표시 방식을 전환하고 미지원 방식에는 이유를 안내한다.
4. 검증된 전선·식생 샘플에서 3D 이격거리를 산출하고 알려진 정답값과 비교해 설정된 허용오차 이내임을 확인한다(허용오차 미확정).
5. 임계값을 변경하면 위험 **후보**가 갱신되며, 거리값과 사용 임계값이 함께 저장된다.
6. 운영 송전 GIS DB는 변경되지 않고, 분석 데이터는 PoC 전용 DB·저장소에만 기록된다.
7. CRS/고도 검증 실패 샘플은 거리 산출을 차단하고 실패 사유를 제공한다.

### 16.2 연동 아키텍처 원칙
```text
[TOMS: LAS 업로드 목록/입력 모달] ---- 업무 API ----> [LiDAR PoC API]
             |                                       |       |
       업로드 건 1건 체크 + [3D 조회]                          |       +--> [파일/점군 저장소]
             |                                       +----------> [PoC PostGIS]
```

### 16.3 수용 기준(acceptance criteria)
1. 등록된 LAS 목록을 열면 필수 열 다섯 가지(사업소, 선로명, 파일명, 용량, 최소이격거리)가 표시되고, 데이터가 없으면 빈 목록 안내가 나타난다.
2. LAS 입력 모달은 대상선로/사업명/파일을 모두 입력해야 업로드 가능하다. 성공 시 파일·선로 매핑·사업소·사업명이 동일 레코드에서 재조회된다.
3. 업로드 직후 자동 최소거리 분석이 실행되지 않았다면 목록에는 **미산출**로 표시되고 허위 `0m`가 나타나지 않는다.
4. **업로드 건 1건** 체크 후 3D 조회 시 새 창이 열리고 해당 건에 속한 LAS/LAZ **모두** 로드된다. 0건 또는 업로드 건 2건 이상 선택 시 안내한다. 다른 업로드 건에 속한 파일은 자동 포함되지 않는다.
5. 3D 화면에서 A/B 점을 선택하면 3D 직선거리(m)와 연결선이 표시된다. 수동 측정값은 목록의 자동 최소거리 필드에 기록되지 않는다.
6. 사용자가 휠 스크롤로 확대·축소, 가운데 버튼 드래그로 회전할 수 있으며, 이 조작 중 임의의 측정점이 추가되지 않는다.
7. 업로드·분석 동작은 운영 TOMS GIS 원본과 운영 DB 데이터를 변경하지 않는다.

## 17. v0.6 — 업로드 건 단위 화면·데이터 계약 (확정)

### 17.1 조회 동작 예시

| 업로드 건 | 선로 | 사업명 | 포함 파일 | 3D 조회 시 표시 |
|---|---|---|---|---|
| UP-001 | A선로 | 1차 측량 | A_01.las | A_01.las 1개 |
| UP-002 | A선로 | 2차 측량 | A_02.las, A_03.las | A_02.las + A_03.las 2개 |

- **A선로 전체 조회가 아니라 업로드 건(UP-001 또는 UP-002) 단위 조회**다.
- 업로드 목록은 업로드 건마다 1행; 파일명은 `A_02.las 외 1건`, 클릭 시 파일 목록 상세 등으로 표기 가능하다.
- 용량은 업로드 건 내 **파일 총합**을 표시하고 개별 파일 용량은 상세에서 확인한다.
- 최소이격거리는 업로드 건을 기준으로 대표값을 표출한다. 미분석 시 `미산출`, 실패 시 `분석 실패`를 표시하고 **파일별 결과 및 업로드 건 통합 최소값**의 산정 규칙을 검증한다.

### 17.2 업로드 팝업 정의

- 사용자 입력: **대상 선로 1개**, **사업명 1개**, **LAS/LAZ 파일 1개 이상(multiple)**.
- 업로드 버튼은 파일 일괄 등록을 요청하고 성공 시 **업로드 그룹 ID**를 생성한다.
- 파일별 포맷·중복·CRS·고도 기준·NIR/Red 속성 검사를 수행한다. 일부 파일 실패 시 **전체 취소/부분 성공 허용 여부는 상세 요구사항에서 확정**한다.
- 파일이 복수인 경우 동일 좌표계·수직 기준 및 인접/중첩 범위의 적합성을 검증한다. 단순 병합만으로 공간적 정합성이 보장된다고 가정하지 않는다.

### 17.3 3D 조회/시각화 정의

- 호출 예시: `/3d?uploadId=<UUID>` (실제 경로·인증은 상세 설계에서 확정).
- 백엔드는 `uploadId`로 소속 LAS 파일 목록 및 분석 결과를 조회하고 접근권한을 검증한다.
- **업로드 그룹 소속 파일만** 3D에 렌더링한다. 서로 다른 파일은 하나의 3D 장면 내에서 공통 좌표계와 고도 기준을 검증한 후 중첩한다.
- 각 파일의 렌더링 성공·실패·진행상태를 확인할 수 있어야 한다. 일부 파일이 로딩에 실패하면 업로드 건 전체가 정상 표시된 것처럼 처리하지 않는다.
- 3D 점 클릭 수동 거리측정과 전선–수목 자동 최소이격거리 분석은 기존 정의를 유지한다.

### 17.4 인수 조건

1. 같은 A선로에 업로드 건 2개를 등록할 수 있고 목록에 각각 나타난다.
2. 첫 번째 업로드 건(파일 1개)을 선택하면 3D 장면에 파일 1개만 표시된다.
3. 두 번째 업로드 건(파일 2개)을 선택하면 3D 장면에 파일 2개가 함께 표시된다.
4. 2번과 3번 모두 **선로가 동일하더라도 서로 다른 업로드 건의 파일이 섞이지 않는다**.
5. 파일이 2개일 때 조작(휠 확대/축소, 휠 드래그 회전, 점 두 개 클릭 거리측정)이 동작하고, 좌표/고도 검증 실패 시 부정확한 거리 결과를 내지 않는다.
